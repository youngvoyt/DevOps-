### 1. Цель работы

Освоение практики построения переносимого решения на базе контейнеров: подготовка образа аналитического приложения, описание многосервисной инфраструктуры в Docker Compose, обеспечение изоляции конфигурации и сохранности данных при перезапусках.

---

### 2. Выполненные работы

В ходе выполнения задания разработана и задокументирована конфигурация, включающая:

- **СУБД PostgreSQL** — хранение нормализованных результатов загрузки и агрегированных метрик;
- **сервис загрузки данных (ETL, init-контейнер)** — однократное чтение набора данных в формате CSV и запись в базу с последующим завершением работы контейнера;
- **веб-приложение аналитики на базе Streamlit** — подключение к базе и отображение расчётных показателей и фрагмента исходных данных;
- **pgAdmin** — графический веб-интерфейс администрирования PostgreSQL (специфика варианта 10).

Сервисы объединены в общую изолированную сеть `backend-network`. Учётные данные и порты вынесены во внешний файл переменных окружения; в файле `docker-compose.yml` секреты не фиксируются. Данные СУБД сохраняются в именованном томе.

---

### 3. Технические решения

**Образ приложения.** Собран по `Dockerfile` с использованием базового образа фиксированной версии `python:3.10.14-slim`, установкой зависимостей до копирования прикладного кода, очисткой кэша пакетных менеджеров и запуском процессов от непривилегированного пользователя (UID 1000). Исключения для сборки заданы в `.dockerignore`.

**Оркестрация.** В `docker-compose.yml` заданы зависимости между сервисами с ожиданием готовности базы данных (проверка работоспособности, *healthcheck*). Приложение инициализируется после успешного завершения ETL-контейнера. Для загрузчика используется монтирование файла исходных данных с хоста в режиме «только чтение».

**Вариант 10.** Дополнительно развёрнут сервис pgAdmin, зависящий от доступности PostgreSQL.

### Приложение. Справочно: воспроизведение среды (Windows, PowerShell)

Ниже приведена последовательность действий, применявшаяся при отладке на рабочей станции с Docker Desktop. Команды носят справочный характер.

Развёртывание из каталога `Lab2/`:

```text
cd Lab2
Copy-Item .env.example .env
docker compose up --build -d
```

При сбоях сборки, связанных с механизмом BuildKit в среде Windows, дополнительно задавались переменные:

```text
$env:DOCKER_BUILDKIT="0"
$env:COMPOSE_DOCKER_CLI_BUILD="0"
```

Проверка состояния:

```text
docker compose ps
```

Доступ к интерфейсам: Streamlit — адрес `http://127.0.0.1:8501` (порт задаётся в `.env`); pgAdmin — `http://127.0.0.1:5050` (аналогично). Параметры входа в pgAdmin и строка подключения к PostgreSQL задаются значениями из `.env`; для поля электронной почты в pgAdmin рекомендуется использовать адрес в общепринятом формате (образ контейнера может отклонять псевдодомены вида `*.local`).

Подключение к СУБД из pgAdmin: хост **`cdap-db`**, порт **5432** (внутренняя сеть контейнеров), имя базы, имя пользователя и пароль — по переменным `POSTGRES_*` в `.env`.

Остановка сервисов:

```text
docker compose down
```

Полное удаление томов с данными:

```text
docker compose down -v
```
